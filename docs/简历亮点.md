# 蓝海商城（lanhai）— 项目亮点与简历说明

本文档用于：**整理本项目可写进简历的要点**、**面试时可展开的技术细节**，并与 **`README.md`**、**`docs/README.md`** 课时体系对齐；**诚实表述个人负责模块**（若仅参与部分服务，勿写成「独立开发全栈」）。

---

## 1. 项目一句话

**基于 Spring Boot 3、Java 17、Spring Cloud Alibaba 的微服务电商后端**：**Spring Cloud Gateway** 统一入口，**Nacos** 注册发现，**OpenFeign** 服务间调用；拆分 **商品、用户、购物车、订单、支付** 等垂直服务；集成 **Redis、MyBatis、支付宝、MinIO**；可选 **service-ai** 对接本机 **Ollama**；**管理端**独立部署。

---

## 2. 技术栈（简历可如实写）

| 类别 | 内容 |
|------|------|
| 运行时 | Java 17、Spring Boot 3 |
| 微服务 | Spring Cloud Alibaba：Gateway、Nacos、OpenFeign（以仓库依赖为准） |
| 数据 | MySQL 8、MyBatis、Redis |
| 中间件与集成 | 支付宝支付与异步回调、MinIO 对象存储 |
| 网关 | 路由、鉴权、与下游服务协作（见课时文档） |
| 可选 | service-ai：HTTP 转发 Ollama，对话与业务解耦 |
| 工程 | Maven 多模块、多 `application-dev.yml`、端口与配置分离 |

**默认开发端口速查**（以各模块 `application-dev.yml` 为准，见根目录 **`README.md`** 表格）：Gateway **8500**、Manager **8501**、各业务服务 **8511～8516** 等。

## 3. 核心亮点（详细）

### 3.1 微服务拆分与治理

- **API 网关**：对外统一 **路由**、**鉴权**（JWT/会话等，以 **`docs/课时05-网关鉴权与Redis会话.md`** 为准）、限流或跨域等横切能力（以代码为准）。
- **注册与发现**：服务注册到 **Nacos**，消费方通过 **服务名** + **Feign** 调用，降低硬编码 URL。
- **模块边界**：**商品、用户、购物车、订单、支付** 等按领域拆分，**独立数据库表** 与 **独立进程**，便于扩展与发布。

### 3.2 典型业务链路（面试可画时序图）

- **购物车 → 订单**：创建订单、库存与价格校验（以实现为准）。
- **订单 → 支付**：调用 **支付宝** 下单、**同步/异步回调** 更新订单状态；**回调验签**、**幂等** 与 **重复通知** 处理是高频考点（见 **`docs/课时08-支付宝接入与回调.md`**）。
- **管理端**：后台 **权限**、**MinIO** 上传与资源访问（见 **`docs/课时09-管理端权限与MinIO.md`**）。

### 3.3 数据与缓存

- **MySQL**：主业务数据；**`db/schema.sql`** 一键建库建表（**`db/README.md`**）。
- **Redis**：会话、缓存或分布式锁等场景（以课时与代码为准）。

### 3.4 可选：AI 助手（差异化）

- **service-ai**：将对话请求 **HTTP 转发** 至本机 **Ollama**，模型名与 URL 可配置（**`docs/课时13-AI助手与Ollama接入.md`**）；体现 **与订单/支付等核心链路的解耦** 与 **可选扩展点**。

### 3.5 工程与可复现性

- **13 课时** + **索引**：从总览、Maven、网关、Nacos/Feign、鉴权、业务拆分、订单与支付、回调、管理端、公共模块、**本地联调**、面试要点到 **Ollama**。
- **`docs/IDEA本地运行与测试.md`**：从打开工程到多服务启动的顺序与依赖（MySQL、Redis、Nacos、密钥等）。

## 4. 简历 Bullet 示例（按需删减、按真实分工修改）

1. 基于 **Spring Boot 3 + Java 17** 与 **Spring Cloud Alibaba**（**Gateway、Nacos、OpenFeign**）搭建 **电商微服务**：拆分 **商品、用户、购物车、订单、支付** 等服务并完成 **本地联调**。
2. 落地 **网关路由与鉴权**、**Redis**、**MyBatis** 数据访问；集成 **支付宝** **下单与异步回调**，关注 **验签、幂等与订单状态机**。
3. 使用 **MinIO** 支持 **管理端** 等资源场景（按你实际参与的模块写细）。
4. （若做过）设计 **service-ai** 通过 **HTTP** 对接 **Ollama**，实现 **AI 能力** 与核心交易链路的 **解耦**；维护 **`db/schema.sql`** 与 **多环境配置**。

**注意**：若 **分布式事务（如 Seata）** 未在项目中落地，面试时如实说明 **「单服务内事务 + 最终一致/补偿」** 或 **「未做分布式事务」**，避免夸大。

## 5. 面试时建议主动说清的边界

- **个人职责**：全栈/某一服务/联调与脚本，与简历一致。
- **与「秒杀」「高并发」**：若无压测数据，写 **架构与链路** 与 **关键技术点**，不写空洞「支撑高并发」。
- **依赖环境**：本地需 **MySQL、Redis、Nacos** 等；生产级 **K8s、链路追踪** 若未做可不说。

## 6. 与 java_job_scheduler（mini-job）的组合叙事（可选）

| 项目 | 侧重点 |
|------|--------|
| **lanhai** | **微服务、网关、业务域、支付与中间件** |
| **mini-job** | **任务调度、重试、幂等、调度中心与执行器分离** |

两者互补：**业务型微服务全链路** vs **调度与协作语义**。
