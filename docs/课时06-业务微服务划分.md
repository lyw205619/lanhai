## 2. 职责边界（业务视角）

### 2.1 service-product（商品）

- **典型能力**：首页、分类、SPU/SKU、搜索、详情。  
- **数据**：商品、类目、品牌等表（以 **mapper XML** 为准）。  
- **特点**：**读多写少**，可 **CDN + 缓存** 优化。

### 2.2 service-user（用户）

- **典型能力**：注册、登录（**颁发 token 并写 Redis**）、个人信息。  
- **与网关关系**：登录成功后 **Redis** 须有 **`user:lanhai:{token}`** 供网关读取。

### 2.3 service-cart（购物车）

- **典型能力**：增删改查购物车行。  
- **设计点**：**未登录购物车**（Cookie/本地）与 **登录合并** 是常见 **扩展题**。

### 2.4 service-order（订单）

- **典型能力**：创建订单、订单列表、状态流转。  
- **难点**：**扣库存**、**优惠券**、**超时关单** — 常跨 **商品/营销** 服务，需 **分布式事务或最终一致**。

### 2.5 service-pay（支付）

- **典型能力**：**支付宝** 下单参数、**异步 notify**、支付单状态。  
- **代码锚点**：`AlipayController`、`AlipayServiceImpl`、`PaymentInfoService` 等。

## 3. 父 POM `lanhai-service` 统一依赖（摘要）

子服务 **无需重复写** 的依赖通常包括：

- `spring-boot-starter-web`  
- `spring-boot-starter-data-redis`  
- `mybatis-spring-boot-starter`  
- `mysql-connector-java`  
- `pagehelper-spring-boot-starter`  
- `spring-cloud-starter-alibaba-nacos-discovery`  
- `common-service`（统一返回与异常）

**好处**：**版本一致**、**改一处全局生效**。  
**注意**：若某服务 **不需要 Redis**，仍引入会 **略增启动依赖** —— 可 **在子模块 exclude**（按需）。

## 4. 数据源与「是否共库」

当前各服务 **`jdbc:mysql://.../db_lanhai`** 多为 **同一库** —— **教学/简化部署** 常见做法：

| 模式 | 优点 | 缺点 |
|------|------|------|
| **共库** | **本地联调简单**、**无跨库 JOIN 限制**（但不建议 **跨服务直连对方表**） |
| **分库** | **故障隔离**、**独立扩容** | **分布式事务**、**数据同步** 成本上升 |

**面试说法**：「当前是 **逻辑拆分 + 物理同库**；生产可 **按域分库**。」

## 5. 包结构建议（阅读代码时）

每个服务一般为：

```
com.liyiwei.lanhai.{product|user|...}
├── XxxApplication.java
├── controller
├── service / impl
├── mapper
└── resources/mapper/**/*.xml
```

---

## 6. 易错点

| 误区 | 正解 |
|------|------|
| 「服务多 = 性能好」 | **网络开销** 增加；优势在 **扩展与边界** |
| 「order 可直接查 product 表」 | **跨服务** 应 **API 或消息**，**禁止** 直接 **耦合对方表**（除非 **明确单体库过渡**） |
