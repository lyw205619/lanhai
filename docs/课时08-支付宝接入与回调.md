# 课时 08：支付宝接入与回调

## 学习目标

1. 能指出 **支付宝 SDK** 在 **Maven** 中的 **引入位置**（父 `dependencyManagement` + 子模块）。  
2. **逐步说明** `AlipayController` 中 **异步通知** `notify` 的 **验签 → 判状态 → 更新本地** 流程。  
3. 解释 **为什么返回字符串 `success`**，以及 **返回其它** 时支付宝的行为。  
4. 区分 **同步跳转（return）** 与 **异步通知（notify）** 的 **权威级别**。  
5. 列出 **沙箱联调** 与 **生产上线** 在 **密钥、网关、回调 URL** 上的差异。

---

## 1. 依赖与配置

### 1.1 Maven

根 `dependencyManagement` 中：

```xml
<dependency>
    <groupId>com.alipay.sdk</groupId>
    <artifactId>alipay-sdk-java</artifactId>
    <version>4.8.73.ALL</version>
</dependency>
```

**service-pay** 模块的 `pom.xml` 中 **实际依赖** `alipay-sdk-java`（**无需重复写版本**）。

### 1.2 配置文件

- 常见：**`application-alipay.yml`** 或 **合并到 `application-dev.yml`**。  
- **敏感项**：**应用私钥、支付宝公钥、APPID** —— **绝不提交** 到公开 Git；**生产** 用 **环境变量或 KMS**。

---

## 2. 控制器：`AlipayController`（源码级导读）

**类注解**：`@Controller` + `@RequestMapping("/api/order/alipay")`  
**注意**：部分方法为 **`@ResponseBody`** 返回 **JSON**；**notify** 返回 **String**。

### 2.1 异步通知 `callback/notify`

**路径**（相对类上 RequestMapping）：`/api/order/alipay/callback/notify`（以源码为准）。

**步骤**：

1. **参数**：`@RequestParam Map<String, String> paramMap` — **支付宝 POST 表单** 所有字段。  
2. **验签**：`AlipaySignature.rsaCheckV1(paramMap, alipayPublicKey, charset, sign_type)`  
   - **失败**：**不可信**，应 **记录日志** 并 **return "failure"**（或按官方文档）。  
3. **交易状态**：`trade_status` 取 **`TRADE_SUCCESS`** 或 **`TRADE_FINISHED`** 表示 **支付成功**（业务上仍要 **幂等更新**）。  
4. **业务更新**：`paymentInfoService.updatePaymentStatus(paramMap)` — **更新本地支付单**、**关联订单状态**。  
5. **返回**：**成功处理** 后 **`return "success"`** — 支付宝 **停止重试**（若仍重试，**业务幂等** 仍要扛住）。

### 2.2 同步「下单」接口

`submitAlipay/{orderNo}` 等 **GET** 接口：  
**拼装** 支付宝 **请求参数**（含 **sign**），**返回** 给前端 **跳转或 form 提交**（具体以 **Service** 实现为准）。

---

## 3. 安全与幂等

| 要点 | 说明 |
|------|------|
| **验签** | **防伪造** 回调；**无验签** 不得更新 **订单** |
| **幂等** | **同一 `out_trade_no`** 多次 notify **只入账一次** |
| **金额校验** | 本地 **应付金额** 与 **支付宝返回金额** **比对**（防篡改） |
| **HTTPS** | 生产 **notify URL** 必须 **HTTPS** 且 **公网可达** |

---

## 4. 本地调试难点

| 难点 | 方案 |
|------|------|
| 支付宝 **无法访问 localhost** | **内网穿透**（ngrok、花生壳、**支付宝沙箱** 回调工具） |
| **签名错误** | 检查 **密钥是否一对**、**字符集**、**是否多空格** |

---

## 5. 本课小结

- **notify** = **支付结果** 的 **权威来源**（相对浏览器同步跳转）。  
- **`success`** = **处理成功** 的 **协议约定**。

## 6. 自测与扩展

1. **打印** `paramMap` 全部 **key**（脱敏后），对照 **支付宝文档** 字段说明。  
2. 在 **`updatePaymentStatus`** 内加 **日志**，验证 **同一订单号** 调用 **两次** 时 **是否重复改状态**。  
3. **扩展**：阅读 **支付宝开放平台**「电脑网站支付」**异步通知** 的 **重试策略**。
